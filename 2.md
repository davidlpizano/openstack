# Componentes principales de OpenStack

OpenStack se compone de servicios independientes que se comunican entre sí mediante **APIs REST** y una **cola de mensajes**. Este documento describe los componentes esenciales, qué hace cada uno, de qué piezas internas se compone y cómo se usa.

## Vista general

| Servicio | Nombre | Puerto API por defecto | Función |
|---|---|---|---|
| Identidad | **Keystone** | 5000 | Autenticación, autorización y catálogo de servicios |
| Cómputo | **Nova** | 8774 | Ciclo de vida de las máquinas virtuales |
| Red | **Neutron** | 9696 | Redes virtuales como servicio |
| Imágenes | **Glance** | 9292 | Catálogo de imágenes de disco |
| Almacenamiento de bloques | **Cinder** | 8776 | Volúmenes persistentes |
| Almacenamiento de objetos | **Swift** | 8080 | Almacenamiento de objetos escalable |
| Colocación | **Placement** | 8778 | Inventario y asignación de recursos |
| Orquestación | **Heat** | 8004 | Despliegue de infraestructura mediante plantillas |
| Panel web | **Horizon** | 80 / 443 | Interfaz gráfica |

## Infraestructura común

Todos los servicios dependen de estas piezas, que **no son** componentes de OpenStack pero son imprescindibles:

- **Base de datos (MariaDB/MySQL):** guarda el estado de cada servicio.
- **Cola de mensajes (RabbitMQ):** comunicación interna entre los procesos de un mismo servicio (por ejemplo, entre `nova-conductor` y `nova-compute`).
- **Memcached:** caché de tokens y datos temporales.
- **HAProxy y Keepalived (en alta disponibilidad):** balanceo de carga y IP virtual para las APIs.

## 1. Keystone (Identidad)

Es la **puerta de entrada** a OpenStack: todo el resto de servicios le pregunta si una petición es válida.

**Conceptos**

- **Dominio:** agrupación de alto nivel de usuarios y proyectos.
- **Proyecto:** unidad de aislamiento de recursos (antes llamado *tenant*).
- **Usuario y grupo:** quién se autentica.
- **Rol:** conjunto de permisos (`admin`, `member`, `reader`) asignado a un usuario en un proyecto.
- **Token:** credencial temporal (formato *Fernet*) que se presenta en cada petición.
- **Catálogo de servicios y endpoints:** lista de servicios disponibles y sus URLs (*public*, *internal*, *admin*).

**Detalles**

- Puede almacenar usuarios en SQL o integrarse con **LDAP / Active Directory**.
- Soporta **federación** (SAML, OpenID Connect) para login único.

```bash
openstack project create --domain default demo
openstack user create --domain default --password-prompt david
openstack role add --project demo --user david member
openstack token issue
```

## 2. Nova (Cómputo)

Gestiona las **instancias** (máquinas virtuales): crearlas, arrancarlas, pararlas, redimensionarlas y migrarlas.

**Procesos internos**

| Proceso | Función |
|---|---|
| `nova-api` | Recibe las peticiones REST |
| `nova-scheduler` | Decide en qué nodo de cómputo se crea cada instancia |
| `nova-conductor` | Intermediario entre los nodos de cómputo y la base de datos |
| `nova-compute` | Se ejecuta en cada nodo de cómputo y controla el hipervisor |
| `nova-novncproxy` | Da acceso a la consola VNC desde el navegador |

**Conceptos**

- **Flavor:** define vCPU, RAM y disco.
- **Par de claves (keypair):** clave SSH inyectada en la instancia.
- **Host aggregate y availability zone:** agrupaciones de nodos para planificación.
- **Cells v2:** particiones que permiten escalar a miles de nodos.

**Hipervisores:** KVM/QEMU (el más usado), además de VMware, Hyper-V, Xen o Ironic para *bare metal*.

```bash
openstack flavor create --vcpus 2 --ram 2048 --disk 20 m1.custom
openstack server create --flavor m1.custom --image ubuntu-24.04 \
  --network red-demo --key-name mi-clave vm-demo
openstack server list
openstack console url show vm-demo
```

---

## 3. Neutron (Red)

Proporciona **redes definidas por software**: redes, subredes, routers, IPs flotantes y cortafuegos.

**Procesos internos**

| Proceso | Función |
|---|---|
| `neutron-server` | API y lógica principal |
| Plugin **ML2** | Marco modular para soportar distintas tecnologías de red |
| Agente L3 | Enrutamiento y NAT (IPs flotantes) |
| Agente DHCP | Reparte direcciones IP a las instancias |
| Agente de metadatos | Sirve metadatos a las instancias |
| Agente OVS / **OVN** | Implementa la red virtual en cada nodo (OVN es el backend moderno por defecto) |

**Conceptos**

- **Red de proveedor (provider):** conecta con la red física del centro de datos.
- **Red de autoservicio (self-service):** red privada creada por el usuario, aislada con VXLAN o Geneve.
- **Tipos de red:** flat, VLAN, VXLAN, GRE, Geneve.
- **Security group:** reglas de firewall por puerto de instancia.
- **Floating IP:** IP pública asignada a una instancia mediante NAT.

```bash
openstack network create red-demo
openstack subnet create --network red-demo --subnet-range 192.168.100.0/24 subred-demo
openstack router create router-demo
openstack router add subnet router-demo subred-demo
openstack router set --external-gateway externa router-demo
openstack floating ip create externa
openstack security group rule create --proto tcp --dst-port 22 default
```

## 4. Glance (Imágenes)

Almacena y cataloga las **imágenes** desde las que arrancan las instancias.

**Detalles**

- **Formatos de disco:** qcow2 (el más habitual), raw, vmdk, iso.
- **Visibilidad:** `private`, `shared`, `community`, `public`.
- **Backends de almacenamiento:** sistema de ficheros local, **Ceph RBD**, Swift, S3 o Cinder.

```bash
openstack image create --file ubuntu-24.04.qcow2 \
  --disk-format qcow2 --container-format bare \
  --public ubuntu-24.04
openstack image list
```

---

## 5. Cinder (Almacenamiento de bloques)

Ofrece **volúmenes persistentes** que se conectan a las instancias como discos. Los datos sobreviven aunque se elimine la instancia.

**Procesos internos**

| Proceso | Función |
|---|---|
| `cinder-api` | Recibe las peticiones REST |
| `cinder-scheduler` | Elige el backend donde se crea el volumen |
| `cinder-volume` | Gestiona el backend de almacenamiento |
| `cinder-backup` | Copias de seguridad de volúmenes |

**Conceptos**

- **Tipo de volumen:** asocia un volumen con un backend o nivel de calidad (SSD, HDD...).
- **Snapshot:** instantánea de un volumen.
- **Arranque desde volumen (*boot from volume*):** la instancia arranca desde un volumen en lugar de un disco efímero.

**Backends habituales:** LVM, **Ceph**, NFS, iSCSI, cabinas comerciales (NetApp, Dell, Pure...).

```bash
openstack volume create --size 20 datos
openstack server add volume vm-demo datos
openstack volume snapshot create --volume datos datos-snap1
```

## 6. Swift (Almacenamiento de objetos)

Almacén de **objetos** (ficheros accesibles por HTTP) altamente escalable y redundante, similar a Amazon S3.

**Procesos internos**

| Proceso | Función |
|---|---|
| Proxy server | Punto de entrada de la API |
| Account server | Gestiona la lista de contenedores de una cuenta |
| Container server | Gestiona la lista de objetos de un contenedor |
| Object server | Almacena los objetos en disco |
| **Ring** | Estructura que determina en qué nodos y discos reside cada dato |

**Detalles**

- Replica los datos (normalmente **3 copias**) o usa *erasure coding*.
- Es **eventualmente consistente**: las réplicas pueden tardar en sincronizarse.
- No es un disco montable: se accede mediante API.

```bash
openstack container create copias
openstack object create copias backup.tar.gz
openstack object list copias
```

## 7. Placement (Colocación)

Antes parte de Nova, es ahora un servicio independiente que lleva el **inventario de recursos** del clúster.

**Conceptos**

- **Resource provider:** entidad que ofrece recursos (por ejemplo, un nodo de cómputo).
- **Inventario:** cantidad de recursos disponibles (vCPU, RAM, disco, GPU).
- **Allocation:** recursos ya consumidos por una instancia.
- **Trait:** característica cualitativa (por ejemplo, `HW_CPU_X86_AVX2`).

Nova le pregunta qué nodos tienen recursos suficientes antes de planificar una instancia.

## 8. Heat (Orquestación)

Permite definir una infraestructura completa en **plantillas YAML** (formato HOT) y desplegarla de forma repetible, equivalente a CloudFormation en AWS.

**Conceptos**

- **Plantilla:** describe los recursos (redes, instancias, volúmenes...).
- **Stack:** conjunto de recursos creados a partir de una plantilla.
- **Autoescalado:** añade o quita instancias según métricas.

```yaml
heat_template_version: 2021-04-16

resources:
  servidor:
    type: OS::Nova::Server
    properties:
      flavor: m1.small
      image: ubuntu-24.04
      networks:
        - network: red-demo
```

```bash
openstack stack create -t plantilla.yaml mi-stack
openstack stack list
```

## 9. Horizon (Panel web)

Interfaz web, basada en **Django**, que permite gestionar la mayoría de los recursos sin usar la línea de comandos. Se comunica con el resto de servicios mediante sus APIs, igual que la CLI.

## Flujo: ¿qué ocurre al crear una instancia?

```
1. Usuario ──► Keystone        Se autentica y obtiene un token
2. Usuario ──► Nova API         Pide crear la instancia (flavor + imagen + red)
3. Nova API ──► Cola (RabbitMQ) Encola la petición
4. Nova Scheduler ──► Placement Consulta qué nodos tienen recursos
5. Nova Conductor ──► Nova Compute  Se elige el nodo destino
6. Nova Compute ──► Glance      Descarga la imagen
7. Nova Compute ──► Neutron     Crea el puerto de red y obtiene la IP
8. Nova Compute ──► Cinder      (Opcional) Conecta un volumen
9. Nova Compute ──► Hipervisor  KVM/QEMU arranca la máquina virtual
10. Neutron DHCP / metadatos    La instancia recibe IP y configuración
```

En cada paso, el servicio que recibe la petición **valida el token con Keystone**.

## Resumen de dependencias

| Servicio | Depende de |
|---|---|
| Nova | Keystone, Glance, Neutron, Placement (y opcionalmente Cinder) |
| Neutron | Keystone, Nova (notificaciones) |
| Glance | Keystone |
| Cinder | Keystone (y opcionalmente Glance para volúmenes de arranque) |
| Heat | Keystone y los servicios que orqueste |
| Horizon | Keystone y los servicios que muestre |
